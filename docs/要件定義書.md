# ラボマッチ 要件定義書 v1.0

最終更新：2026-05-22
（会話による要件定義 v0.1〜v0.3 を統合・確定）

---

## 1. 背景・目的

- 大学院進学・研究室配属を控えた学生が、興味分野に合う研究室を効率よく発見・比較できる場がない。
- 既存の researchmap / KAKEN / 日本の研究.com は研究者個人・課題単位で、研究室を横断検索・比較する用途に向かない。
- ラボマッチは、分野・大学・所属学会の軸で研究室を検索でき、研究内容を AI 要約で平易に把握できる Web サイトを提供する。
- 長期ビジョン：生命科学系から始め、理系全体、最終的に文系を含む全学術分野を網羅する。

## 2. 想定ユーザー

- 主要ユーザー：進学先（大学院・研究室）を探す学生（学部生〜修士）。
- ニーズ：興味分野からの研究室発見、研究内容の平易な把握（AI 要約が中核価値）、活発さ・実績の確認、候補の比較と応募導線。
- 将来の副次ユーザー：共同研究を探す研究者、産学連携の企業。

## 3. 前提・制約

- 運用主体は個人 1 名。長期的に大学等への所属がない前提で設計する（現状の所属に依存しない）。→ 低運用負荷を最優先（マネージド／サーバーレス、自動化バッチ、低タッチな問い合わせ対応）。恒常コストは個人負担。
- 将来的に全学術分野・全国規模（数万〜十数万研究室）を想定。→ 分野タクソノミ・データモデル・検索基盤を最初から分野非依存かつスケール可能に設計する。
- 初期データは生命科学系のみだが、構造は全分野対応で作る（後からの作り直しを避ける）。
- データ取得は公式 API をバックボーンとし、スクレイピングは保守可能な範囲のベストエフォートに限定する。

## 4. スコープ（段階拡大）

- フェーズ 1（MVP）：生命科学系
- フェーズ 2：理系全体（科研費審査区分の理工・農・医歯薬系へ拡大）
- フェーズ 3：文系を含む全分野（人文学・社会科学）

各フェーズで対象分野を広げつつ、機能も拡充する（第 11 章 リリース計画を参照）。

## 5. 機能要件

### 5.1 検索・絞り込み
- 検索軸：分野（統制語彙）／大学／所属学会／フリーキーワード
- フィルタ候補：地域、職位、科研費の採択有無、成果数レンジ
- ソート：関連度、成果数、科研費採択額、更新日
- 分野の統制語彙：科研費「審査区分表」を採用（人文・社会科学まで全分野を網羅し、KAKEN データと直結できる）。
- 「所属学会」での検索は、学会所属データの取得可否に依存する（6.1・第 12 章を参照）。

### 5.2 検索結果一覧
- 研究室カード：研究室名／主宰者／大学・学部／分野タグ／AI 要約の冒頭／成果数などの指標
- ページネーション、ヒット件数表示

### 5.3 研究室詳細ページ
- 基本情報：研究室名、主宰者（教授）、所属（大学・学部・学科）、所在地
- 直近 5 年の研究成果の AI 要約文（中核コンテンツ）
- 研究キーワード／分野タグ
- 研究成果リスト（直近 5 年、出典リンク付き）
- 科研費の採択履歴（課題名・期間・区分）
- 所属学会と役職（取得できた範囲。データ源未確保の場合はベストエフォート表示）
- 外部リンク：researchmap / KAKEN / 日本の研究.com / 研究室公式サイト
- メンバー構成・連絡先（取得できた場合）
- 文系では「研究室」がゼミ／研究者個人に近い。ページ単位は教授単位で共通とし、ラベル（研究室／ゼミ）は分野で可変にする。

### 5.4 その他（MVP では任意）
- 研究室の比較（2〜3 件並置）
- お気に入り保存
- 情報修正・掲載停止の申請フォーム

## 6. データ要件

### 6.1 データソース

| ソース | 取得方式 | 主用途 | 可否 |
|---|---|---|---|
| OpenAlex | API | 論文メタデータ・アブストラクト（AI 要約の入力） | 利用可（CC0・商用可）。論文データの主軸 |
| KAKEN | API（要アプリ ID） | 科研費課題・分野・審査区分 | 利用可（CC BY 相当・出典明記で商用可） |
| researchmap | API（要利用申請） | 所属学会・委員歴・研究キーワード・業績 | 要照会（個人/商用の利用可否が不明） |
| CiNii Research | API（要開発者登録） | 和文の論文・著書（文系で重要） | 要照会（商用可否が不明） |
| 日本の研究.com | リンクのみ | 外部リンク掲出 | 不可（スクレイピングしない／リンク掲出に限定） |

- 個人運用・大学非所属の前提のため、researchmap API が利用できない可能性を織り込む。中核機能（検索・AI 要約）は **OpenAlex ＋ KAKEN だけで成立する設計**とし、researchmap は「取得できれば付加する」拡張データと位置づける。
- 「所属学会・役職」は researchmap への依存度が高く、利用不可の場合はベストエフォート項目とする（J-GLOBAL 等の代替調査、または各学会サイトからの役職情報収集を検討）。
- 短時間の大量アクセスは KAKEN・CiNii ともにブロックされ得るため、レート制御を実装する。

### 6.2 データモデル（分野非依存）
- 研究室の識別子：主宰者の研究者番号（e-Rad ID）を主キー候補とし、researchmap ID と紐付ける。
- 主要エンティティ：研究室／研究者／研究成果（論文・著書・その他を包含）／科研費課題／学会／大学・組織。
- 研究成果エンティティは論文に限定せず、文系の著書・その他成果物も表現できる構造にする。

### 6.3 名寄せ
- 段階適用：
  1. 永続識別子（研究者番号 → ORCID → researchmap ID）で確定。
  2. 残りを確率的レコードリンケージで照合（氏名類似度・所属・分野・キーワード・共著者・DOI 集合の重なりをスコアリングし、閾値で自動確定／要レビューに振り分け）。
  3. 低信頼度のみ人手レビュー。
- MVP（生命科学系）は規模が小さく人手レビューも現実的。全分野展開時はレビュー対象を閾値で限定する。

### 6.4 AI 要約
- 入力：直近 5 年の研究成果（理系＝論文中心、文系＝論文＋著書）のタイトル＋アブストラクト。
- 出力：学生にも分かる平易な日本語の研究室紹介文（完全オリジナル文）。アブストラクトの著作権は出版社にあるため転載しない。「AI 生成・誤りを含む可能性」を明記する。
- LLM：Claude Haiku を採用。共通の指示文はプロンプトキャッシュに載せてコストを抑制する。実装上は LLM 呼び出しを差し替え可能なインターフェースにしておく。
- 生成方式：オンデマンド。検索用メタデータは全件取り込むが、AI 要約は研究室ページの初回閲覧時に生成・キャッシュする。閲覧されない研究室の生成コストを回避する。成果に差分が出たら再生成する。

### 6.5 更新頻度
- API 由来の検索用データ：月次バッチ。
- AI 要約：初回閲覧時に生成、以後は成果差分時に再生成。
- スクレイピング：低頻度・低負荷。

## 7. 非機能要件

- スケーラビリティ：将来 数万〜十数万研究室・相応の検索量に耐える検索・データ基盤。
- 低運用負荷：個人運用前提。マネージド／サーバーレス中心、監視・バッチを自動化。
- SEO：学生は検索流入が中心 → 研究室ページを SSG/ISR でインデックス可能にする。
- レスポンシブ対応（スマホ閲覧を想定）。
- 検索応答：数百 ms〜1 秒程度。
- 可用性：標準的な水準。

## 8. 法務・コンプライアンス

- 著作権：論文アブストラクトの転載不可。AI 要約は必ずオリジナル文。
- API 利用規約：KAKEN は出典明記（CC BY 相当）。researchmap は利用申請が必要で、個人/商用の可否を事前確認する。CiNii Research は商用可否を事前確認する。各 API のレート制限を遵守する。
- スクレイピング：日本の研究.com はリンク掲出のみとし、スクレイピングしない。研究室公式サイトを扱う場合も robots.txt・規約を遵守し、低頻度で行う。
- 個人情報：研究者名・所属は公開情報だが、個人を集約するサイトであり運営は個人。掲載停止・修正の申請フォームを設け、対応を低タッチにする。プライバシーポリシー・運営者情報を明記する。
- 広告：アフィリエイト・広告は「広告／PR」と明示する（ステマ規制・景品表示法、2023 年 10 月から規制対象）。
- 免責表示：AI 要約・自動収集データの誤りに関する免責を明記する。

## 9. 収益化計画

目的：複数の収益源を組み合わせ、サイト全体で黒字化する。

- ディスプレイ広告（Google AdSense 等）：ベースライン。低単価・トラフィック依存。
- アフィリエイト（学生導線に整合するもの）：参考書・問題集、英語試験対策（TOEFL/TOEIC）、院試予備校、PC・タブレット、進学に伴う賃貸・引越し、奨学金・就活サービス。
  - 情報商材アフィリエイトは、中核資産である「進路情報サイトとしての信頼性」と衝突するため対象外とする。
- 法人向け有料プラン（将来の本命）：企業の採用・産学連携用途。研究室への一括コンタクト、詳細フィルタ、分析機能等。
- 寄付・サポーター：学術系サイトと相性が良い。月額サポーター等。
- 収益見通し：コンシューマ向け広告は RPM が低く、広告のみで黒字化には相当のトラフィックが必要。学生向けは広告＋整合性の高いアフィリエイトで運用コストを賄い、黒字化の主軸は将来の B2B（法人向け有料プラン）と位置づける。

## 10. 技術構成（技術設計フェーズで確定）

※ 本章の構成は『技術設計書 v1.0』で確定済み。個人運用・初心者保守を考慮し、全体を TypeScript に統一し、MVP では専用検索エンジンを使わず PostgreSQL で代替する。以下は初期のたたき台。

- フロント：Next.js。研究室ページは ISR（初回アクセスで生成＋キャッシュ。AI 要約のオンデマンド生成と相性が良い）。
- 検索：Meilisearch / Typesense など（十数万件規模に対応、マネージド利用も可）。
- DB：PostgreSQL（マネージド）。
- データ基盤：Python バッチ（API 取り込み・名寄せ・限定スクレイピング・AI 要約生成）。
- LLM：Claude（Anthropic API）の Haiku クラス。
- ホスティング：低運用負荷・低コストを重視（マネージド中心）。

## 11. リリース計画

- フェーズ 0：データソースの規約照会、データモデル設計、ドメイン取得、技術設計。
- フェーズ 1（MVP）：生命科学系。OpenAlex ＋ KAKEN 中心の取り込み、基本検索＋研究室詳細＋ AI 要約（オンデマンド）。
- フェーズ 2：理系全体へ拡大。フィルタ拡充、比較機能、限定スクレイピング追加。
- フェーズ 3：文系を含む全分野へ拡大。研究者個人ページ、お気に入り等。
