# ラボマッチ 技術設計書 v1.0

最終更新：2026-05-22
対象：要件定義書 v1.0 に基づく MVP（生命科学系）の技術設計

---

## 0. 設計方針

本プロジェクトは個人 1 名（Web 開発はほぼ初心者）が長期運用する。実装は Claude が主導し、ユーザーはレビューと動作確認を行う。これを踏まえ、次を最優先方針とする。

- **シンプルさ最優先**：構成要素・サービス・言語の種類を最小化する。
- **1 言語に統一**：フロント・サーバー・データ取り込みをすべて TypeScript で書く（Python は使わない）。学習・保守の対象を 1 つに絞る。
- **マネージドサービス中心**：サーバー管理をしない。無料枠から始められるものを選ぶ。
- **MVP は最小構成**：専用検索エンジンなど、後から足せるものは最初は入れない。

## 1. 全体アーキテクチャ

システムは 3 つの部分からなる。

1. **Web サイト（フロント＋サーバー）** — Next.js。利用者がブラウザで見る画面と、その裏側の処理。Vercel 上で動く。
2. **データベース** — PostgreSQL（Neon）。研究室・論文・科研費などの全データを保存。検索もここで行う。
3. **データ取り込みスクリプト** — TypeScript で書いた小さなプログラム群。OpenAlex と KAKEN の API からデータを取得し、データベースに書き込む。定期的に実行する。

データの流れ：

- 【定期実行】取り込みスクリプト → OpenAlex・KAKEN から取得 → 整形・名寄せ → PostgreSQL に保存
- 【閲覧時】ブラウザ → Next.js（Vercel）→ PostgreSQL を読む → 画面を表示
- 【研究室ページ閲覧時】AI 要約が未生成なら → Claude（Haiku）で生成 → PostgreSQL に保存 → 表示。次回以降は保存済みを使う。

## 2. 技術スタック（確定）

| 領域 | 採用技術 | 選定理由 |
|---|---|---|
| 言語 | TypeScript | 全体を 1 言語に統一。Next.js と同じ言語でデータ取り込みも書ける。 |
| Web フレームワーク | Next.js（App Router） | 画面・サーバー処理・SEO（SSG/ISR）を 1 つでまかなえる。 |
| データベース | PostgreSQL（Neon） | 定番。無料枠が大きく、サーバー管理不要。データ保存と検索の両方を担う。 |
| DB アクセス | Prisma | スキーマ定義が分かりやすく、付属の Prisma Studio でデータを GUI で確認できる（初心者に優しい）。 |
| 検索 | PostgreSQL（pg_trgm 拡張） | MVP 規模では専用検索エンジン不要。分野・大学などの絞り込みとキーワード検索を DB で行う。 |
| AI 要約 | Anthropic API（Claude Haiku） | 要件で確定済み。TypeScript 用 SDK がある。 |
| ホスティング | Vercel（Web）＋ Neon（DB） | どちらも無料枠から開始でき、GitHub 連携で自動デプロイ。 |
| ソース管理 | GitHub | コード管理と Vercel へのデプロイの起点。 |

将来：検索精度や規模が必要になったら Meilisearch（日本語対応の検索エンジン）を追加できる。スクレイピングが必要になった段階で取り込みスクリプトを拡張する。

## 3. データモデル

PostgreSQL に以下のテーブルを置く（MVP の主要なもの）。詳細は Prisma の schema ファイルで一元管理する。

- **universities（大学）** — 大学名、所在地（都道府県）など。
- **labs（研究室）** — 中心テーブル。1 行＝1 研究室（＝主宰者の教授）。大学への参照、研究室名、主宰者名、学部・学科、公式サイト URL、研究者番号（e-Rad）、外部 ID（OpenAlex 著者 ID、researchmap ID 等）、AI 要約テキスト、AI 要約の生成日時。
- **works（研究成果）** — 論文・著書など。研究室への参照、タイトル、要旨、発表年、DOI、出典 URL、種別。
- **grants（科研費課題）** — 研究室への参照、課題名、期間、金額、審査区分、KAKEN URL。
- **fields（分野）** — 科研費「審査区分表」に基づく分野マスタ。階層構造（親分野への参照）。
- **lab_fields** — 研究室と分野の対応（多対多）。
- **societies（学会）／lab_societies** — 所属学会用。researchmap 依存のため MVP では空でよい（後日投入）。

## 4. データ取り込みパイプライン

`scripts/` 配下の TypeScript スクリプトとして実装し、`npm run ...` で実行する（MVP では手元で手動実行。将来 GitHub Actions 等で自動化）。

1. **大学・分野マスタの準備** — 対象大学リストと、科研費審査区分の分野マスタを投入。
2. **KAKEN 取り込み** — 生命科学系の審査区分で科研費課題を取得。研究代表者＝研究室主宰者として labs を作成し、grants を保存。研究者番号で識別する。
3. **OpenAlex 取り込み** — 各研究室主宰者の直近 5 年の論文を取得し works に保存。著者の名寄せは OpenAlex 著者 ID・ORCID・氏名＋所属で行う。
4. **名寄せ** — 研究者番号 → ORCID → 氏名＋所属 の順で同一人物を確定。曖昧なものはスコアリングし、低信頼は保留（MVP は件数が少ないので手動確認も可）。
5. **分野タグ付け** — 科研費の審査区分から lab_fields を設定。

MVP はまず **1〜数大学の生命科学系**に絞って通し、品質を確認してから対象を広げる。KAKEN を「研究室の種リスト」に使うことで、研究が活発な研究室を自然に拾える。

## 5. 検索の仕組み（MVP）

- **絞り込み（ファセット）**：分野・大学（都道府県）・所属学会。SQL の JOIN と WHERE で実現し、件数も同時に集計。
- **キーワード検索**：研究室名・主宰者名・研究キーワード・論文タイトルを対象に、PostgreSQL の `pg_trgm` 拡張で部分一致・あいまい一致。
- **並び順**：関連度、成果数、科研費採択額、更新日。
- MVP 規模（生命科学系で数千〜数万研究室）では PostgreSQL で十分な速度が出る。

## 6. AI 要約の仕組み

- **生成タイミング**：研究室詳細ページが初めて表示されたとき（オンデマンド）。Next.js のサーバー側処理で行う。
- **手順**：labs の AI 要約が空 → その研究室の直近 5 年の works（タイトル＋要旨）を集める → Claude Haiku に渡し、学生向けの平易な紹介文を生成 → labs に保存 → 表示。次回以降は保存済みを返す。
- **コスト対策**：共通の指示文はプロンプトキャッシュに載せる。閲覧された研究室だけ生成されるため、無駄なコストが出ない。
- **品質・法務**：要旨の転載はせず完全オリジナル文。「AI 生成・誤りを含む可能性」を明記。
- ページ表示は Next.js の ISR を使い、生成済みページはキャッシュから高速に返す。

## 7. 画面構成（MVP）

- **トップページ** — サービス説明、分野からの入口、検索ボックス。
- **検索結果ページ** — 左に絞り込み（分野・大学・学会）、右に研究室カードの一覧。
- **研究室詳細ページ** — 基本情報、AI 要約、研究キーワード、論文リスト、科研費履歴、所属学会・役職、外部リンク。
- すべてスマホ対応（レスポンシブ）。研究室詳細は SEO のため静的に近い形で配信。

## 8. リポジトリ構成

GitHub に 1 つのリポジトリ。Next.js プロジェクトの中に取り込みスクリプトも同居させる。

```
labmatch/
  app/                      画面（トップ／検索／研究室詳細）
  components/               画面の部品
  lib/                      共通処理（DB接続、外部API、AI要約）
  scripts/                  データ取り込みスクリプト
  prisma/schema.prisma      データベース定義
  package.json
```

## 9. デプロイ・運用

- **コード**：GitHub に置く。
- **Web サイト**：Vercel が GitHub と連携し、push すると自動デプロイ。
- **DB**：Neon（PostgreSQL）。接続情報を Vercel の環境変数に設定。
- **必要なアカウント**：GitHub、Vercel、Neon、Anthropic（API キー）。実装開始時に順に作成する。
- **データ更新**：MVP では取り込みスクリプトを手元で手動実行。安定したら自動化。

### コスト概算（MVP）
- 開発・公開前：ドメイン（labmatch.jp、年 約 2,000〜4,000 円）と、AI 要約の試用ぶんの API 利用料（少額）のみ。Vercel・Neon は無料枠。
- 収益化（広告掲載）開始後：Vercel は商用利用に Pro プラン（月 約 20 ドル）が必要。Neon も規模に応じ有料へ。AI 要約 API はアクセス数に比例。
- ※ Vercel の商用条件が気になる場合、Cloudflare Pages 等の代替も後で検討可能。

## 10. MVP 実装計画

小さく動かしながら進める。各ステップで動作を確認する。

- **ステップ 1：土台づくり** — GitHub / Vercel / Neon のアカウント作成、Next.js プロジェクト作成、空ページを Vercel に公開。
- **ステップ 2：データベース定義** — Prisma でテーブルを定義し、Neon に作成。
- **ステップ 3：データ取り込み（小さく）** — 1 大学の生命科学系を対象に KAKEN・OpenAlex から取り込み、DB に少量のデータを入れる。
- **ステップ 4：研究室詳細ページ** — DB の 1 研究室を表示するページを作る（AI 要約はまだ仮）。
- **ステップ 5：AI 要約** — Claude Haiku でオンデマンド要約を組み込む。
- **ステップ 6：検索・一覧** — 検索結果ページと絞り込みを作る。
- **ステップ 7：トップページと仕上げ** — トップページ、レスポンシブ調整、公開。

ステップ 1〜4 で「データが入って 1 ページ表示できる」縦の一本（最小スライス）が通る。そこから機能を足していく。
